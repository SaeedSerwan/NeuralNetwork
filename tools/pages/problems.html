When training goes wrong.

Three classic problems: a model that is 98% accurate and useless, a deep network whose first layers never learn, and a loss that suddenly becomes NaN. For each one: the symptom, the cause and the fix, and an experiment you can run.

01Data imbalance: when 98% accuracy means nothing

MNIST is balanced: about 10% of each digit. Fraud data is not. Below are 10,000 simulated card payments, 2% of them fraud; 3,000 are held out for testing. A model that simply says “legitimate” every time is 98% accurate and catches no fraud at all. Train a logistic regression (one sigmoid neuron) on the data as it is: the cost function is dominated by the 98%, so the model learns that “legitimate” is almost always right.

Catch the fraud

Pick a strategy, then move the threshold. Red crosses: fraud. Grey dots: a sample of the legitimate payments.

\[ \text{recall} = \frac{TP}{TP + FN} \qquad \text{precision} = \frac{TP}{TP + FP} \]

Key idea: judge a model on a rare class by recall and precision, not accuracy. Rebalancing finds more fraud but raises false alarms: where to stand is a business decision.

02Fixing imbalance: resample, reweight, measure

SMOTE (Chawla et al., 2002) creates synthetic minority examples: pick a fraud, pick one of its nearest fraud neighbours, and place a new point somewhere on the line between them.

SMOTE, one point at a time

Each click adds synthetic frauds between real ones (k = 3 nearest neighbours).

reweight

Class weights

A missed fraud costs more in the cost function, e.g. 49 times as much as a false alarm, so the model can no longer ignore it.

resample

SMOTE or undersampling

Add synthetic frauds, or throw away part of the legitimate payments. Resample the training set only, never the test set.

measure

Recall, precision, F1

And tune the threshold: lowering it catches more fraud and raises more false alarms.

03Vanishing gradients

Backpropagation multiplies the gradient by one weight and one activation slope per layer on its way back. The slope of the sigmoid is never more than 0.25. Multiply ten numbers smaller than 0.25 and almost nothing is left: the first layers receive a gradient close to zero and hardly change.

\[ g_1 = g_L \cdot \prod_{l=2}^{L} w_l\,\sigma'(z_l) \]

Gradient size in every layer

A real network of 32 neurons per layer, 64 random inputs. Bars use a log scale: each grid line is 10 times smaller.

Symptom: the loss stops falling and the first layers hardly change.

04Exploding gradients

The same multiplication can go the other way. If the repeated factor is a little larger than 1, the product grows without limit: 1.1 multiplied 100 times is about 14,000. This happens in very deep networks and in RNNs on long sequences, where the same weights are multiplied once per time step (backpropagation through time).

A product of repeated factors

Log scale. The dashed line is 1.

Symptom: the loss jumps or becomes NaN. Fix: gradient clipping, the standard fix for RNNs: if the gradient is too long, shrink it to a maximum length before stepping. Also a smaller learning rate, good initialisation, LSTM / GRU.

\[ \text{if } \lVert g \rVert > c:\quad g \leftarrow c\,\frac{g}{\lVert g \rVert} \]

A cliff in the cost landscape

RNN cost surfaces have steep walls. Run it, then tick clipping and run again.

Question

The loss falls for 300 steps, then becomes NaN. Which problem? First fix? An exploding gradient. First fix: gradient clipping (and/or a smaller learning rate).
